# LINE 購買連動リッチメニュー自動切替システム（模擬案件9）

D2C 定期通販ブランド「コーヒー定期便」の LINE 公式アカウント向けに、
**購入履歴に応じて、顧客ごとにリッチメニューを自動で出し分ける**管理システム。
AI エンジニアリングの模擬案件（案件 9）。

> **リッチメニューとは**：LINE のトーク画面の下部に常時表示される、タップできるメニュー画像のこと。
> 通常は全員に同じものが出るが、LINE の API を使うと「この人にはこのメニュー」と個別に出し分けられる。

| #   | 機能                   | 概要                                                                                                               |

| 2   | 注文データの取り込み   | CSV をアップロード。注文 ID で重複を除きながら積み上げる（再アップロードしても二重計上しない）                     |

| 5   | 管理画面               | メニュー画像の登録とプレビュー、閾値設定、顧客一覧（絞り込み）、手動再割当、処理状況の表示、未紐付け顧客への再案内 |
| 6   | AI サマリー            | 「今月のセグメント構成」を AI が短く要約（画面に「AI による要約」と明示）。切替の判断には一切使わない              |

### セグメントの判定ルール（上から順に判定し、最初に当てはまったもので確定）

| 順  | 条件                                                  | セグメント     |
| --- | ----------------------------------------------------- | -------------- |
| 1   | 購入回数が 1 回以下                                   | **新規**       |
| 2   | 累計購入額が VIP 閾値以上（初期値 ¥30,000）           | **VIP**        |
| 3   | 最終購入日が「基準日の 6 ヶ月前」以降（その日を含む） | **リピーター** |
| 4   | 上記以外                                              | **休眠**       |

- 1 回しか買っていない人は、1 回で高額でも「新規」（1 順目で確定するため）
- VIP は最終購入が古くても VIP のまま（2 順目で確定するため）
- 判定は「基準日」を引数に取る関数にして、テストでは基準日を固定する（日付が変わっても結果がぶれないように）

## アーキテクチャ設計の要点

```
運用担当者（マーケ）
  → Next.js on Vercel（管理画面 / CSV 取り込み / セグメント判定）
      ├→ Supabase（顧客・注文・紐付けコード・メニュー設定）
      ├→ LINE Messaging API（リッチメニュー作成・ユーザーへの紐付け）
      └→ AI Gateway 経由の Claude（セグメント構成の要約コメントのみ）

LINE 友だち → Webhook（コード入力の受け口）→ 顧客と LINE ユーザーを紐付け
```

設計判断とその理由（詳細は `CLAUDE.md`）：

- **判定はルール、AI は要約だけ**：誰がどのメニューになるかを後から説明できるようにするため
- **注文は注文 ID で重複排除して積み上げ**：累計購入額で判定するので、再アップロードで数字が変わっては困る
- **変化した顧客だけ LINE API を呼ぶ**：無駄な呼び出しと失敗の巻き込みを減らすため
- **LINE の一括紐付け API を使う**（LINE 公式仕様で存在を確認済み）：1 人ずつ呼ぶより速く、失敗の管理もしやすい

## 模擬案件としての制約

- LINE 公式アカウントの実運用（本番の友だち・課金プラン）は行わず、テスト用アカウントで動作確認する想定
- EC サイトとは接続しない（注文は CSV 取り込みのみ）。1 行 = 1 注文で、1 注文に複数商品がある形は扱わない
- 注文が 1 件も無い友だちは対象外（紐付け用コードが発行されないため、デフォルトメニューのまま）
- 顧客数は数十〜百人規模を想定した簡易実装。数千人規模の非同期キュー化は Phase 2
- LIFF（LINE アプリ内で開く Web ページ）でのログインは使わず、コード入力方式にする
